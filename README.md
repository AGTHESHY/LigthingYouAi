# 成长角色档案与世界书

AstrBot 插件：按场景加载角色卡，在**实际压缩上下文时**集中更新角色记忆和宏观世界书。普通轮次不重写角色档案，主模型直接参考尚未压缩的剧情历史。

## 安装与模型选择

1. 在 AstrBot 插件页面使用仓库地址 `https://github.com/AGTHESHY/LigthingYouAi` 安装或更新插件。
2. 选择包含角色与世界设定的人设。首次使用会拆分角色卡、固定规则和世界书，这是一次性初始化。
3. `decision_provider_id` 可选，填写 AstrBot **模型提供商 ID**，不是密钥、网址或原始模型名。

| 配置 | 场景与原子判断 | 压缩时的文字提取 |
| --- | --- | --- |
| 留空 | 当前会话 LLM，严格校验 JSON | 当前会话 LLM |
| 指定聊天模型 | 指定模型，严格校验 JSON | 指定模型 |
| 指定 Jev 等原生决策模型 | 原生 Noul 批量判断 | 当前会话 LLM |

插件复用 AstrBot 的模型凭据，无需另外配置 API Key。没有 Jev 完全可以使用；LLM 回退返回布尔值，不伪造概率。这里的 JSON 支持是提示词输出加本地严格校验，并不假定每个模型适配器都支持原生 JSON Schema 约束。

当前验证本体：`feb3e82c3`，AstrBot `4.30.0-beta.1`。未验证旧版或第三方 Agent 的兼容性。

## 人设接管与配置继承

接管 AstrBot **最终解析生效的人设正文**，包含默认选中人设、全局或会话继承得到的人设。原始完整正文被动态角色卡与世界书替换，不再叠加两份。

保留外围安全指令、技能、工作区和工具指令；模型、平台、工具权限及其他配置仍由 AstrBot 管理。原始人设文件不会被修改。

固定公共规则始终注入，包括用户独占玩家角色控制权、叙事方式、力量层级、禁止擅自解决的核心矛盾。玩家也可以有认知档案，但 `controller=user` 不代表允许 AI 扮演玩家。

## 普通轮次

- 只做角色选择和本地资料检索，不提取状态变化、成长或世界事件，不写入角色／世界书文件。
- 场景路由仅发送角色名册、上次在场名单、最近少量对话及当前输入，不发送完整角色卡和世界书。
- 每个角色的“实际在场”与“正在被讨论”是两个独立判断，合并成一次请求。被提及的离场角色标记为 `referenced`，不会据此自动入场。
- 没有新的角色提及或场景线索时复用场景选择，不额外调用模型。
- 只注入选中角色。记忆按本地相关性与时间检索，每角色最多 12 条；相关势力最多 6 个，世界事件最多 8 条，完整记录仍保存在档案里。
- 档案代表上次压缩时的状态，尚在历史中的更新事实优先；不会因为尚未再次压缩就把已经康复的人物演回受伤。

## 真正触发压缩时

1. 由 AstrBot 自己决定什么时候压缩或截断，插件不模拟 token 阈值，也不将普通请求当成压缩事件。
2. 保留压缩前的完整快照，比较压缩结果，找出**实际被移除的历史前缀**；仍保留的近期历史不提前归档。
3. 有 Jev 时先用小状态筛选是否存在值得归档的角色或世界事实，明确没有时跳过昂贵的档案提取。
4. LLM 提取原子候选，每条只改变一个角色的一个字段，或一个宏观世界事实，并逐字引用原始历史为依据。
5. 批量核验每个候选：原文支持、实际发生、是否违反固定规则、最新状态，以及需要时的角色知情或宏观归属。固定规则检查与状态变化判断分开。仅不确定的压缩核验题升级到 LLM JSON，不在普通轮次进行重型整理。
6. 保存通过核验的事实，再以“简短公共剧情摘要＋未压缩的近期历史”衔接。已归档的角色经历由角色卡加载，不必在公共摘要里再次长篇重复。

公共摘要仍保留当前场景、未完成事件与剧情衔接，不会把压缩后的上下文全部删除。未通过核验的事实保留相关原文或核心压缩器的摘要；接口、结构或存储失败时保留压缩前历史，不静默丢失剧情。JSON 多余字段至多尝试一次结构修复，修复不能改变事实或证据。

## 角色与世界书的边界

| 资料 | 内容 | 更新方式 |
| --- | --- | --- |
| 固定世界规则 `world` | 用户控制权、叙事限制、固定力量规则 | 初始化后不让剧情模型改写 |
| 角色核心 `core` | 身份、外貌、性格底线、绝对禁忌、永久特征 | 初始化后不让剧情模型改写 |
| 角色 `state` | 身体、位置、人物间私人关系等单项事实 | 只在压缩时逐项更新 |
| 角色 `knowledge` | 角色知道、误信或不知道的事 | 独立更新，不能当作世界客观事实 |
| 角色 `growth`、`memories` | 有依据的成长与重要经历 | 只在压缩时更新，旧经历保留 |
| 世界书 `facts` | 年份、局势等宏观可变状态 | 只在压缩时更新 |
| 世界书 `factions`、`relations` | 组织状态及组织间的联盟、敌对、臣属等 | 与人物私人关系独立 |
| 世界书 `events` | 重大宏观事件 | 追加保存 |

例如伤势可从“未愈”变成“痊愈”，受伤及康复经历仍保留；永久失去的能力不能被普通伤势恢复覆盖。两国结盟不会把两个具体人物之间的敌意自动改成友好。一个人知道秘密，不会自动更新其他人的认知；错误信念与客观事实分开保存。

所有世界与角色资料都是叙事者参考，不代表在场角色自动知道其中所有秘密。语义理解仍依赖模型，不能保证完全没有误判。

## 接入实现与持久化

本体目前没有公开独立的压缩插件事件。插件通过 `on_agent_begin` 识别**当前原生会话的 runner**，仅包装其 `ContextManager.process` 实例；不修改 AstrBot 文件，不替换全局类，不影响其他会话。包装器观察实际移除的历史，结束或卸载时恢复。未知运行时无法绑定时，本轮恢复原人设并记录提示，不假装已安装压缩归档功能。

这是依赖已验证本体内部结构的适配层，升级 AstrBot 后需要重新验证。原生 LLM 摘要仍由本体生成，插件只在真正压缩时额外整理档案；不是完全免除压缩成本。

档案放在 `data/plugin_data/astrbot_plugin_living_characters/`，按消息来源、对话 ID、选中人设和原文内容隔离，使用原子替换保存。v0.1 的旧状态文字会本地迁移为历史快照，保留旧记忆；更明确的新单项状态优先于旧快照。修改原人设内容或新建对话会使用新的独立档案。

## 验证

48 项自动化回归测试全部通过，覆盖：普通轮次零成长写入、无场景线索时零额外调用、本体真实 token 压缩及轮次截断、未移除历史不提前归档、失败保留原文、原子判断、Jev 不确定性升级、LLM JSON 类型校验及受限修复、宏观与人物关系分离、玩家控制权、秘密与错误认知隔离、迁移和卸载恢复。

真实接口使用仓库中的中性样例验证：`deepseek-chat`、Jev 官方 `jev-latest` 及 AstrBot 实际适配器。不需要，也未在仓库中保存测试密钥、私人角色设定或运行数据。

在独立 Conda 或 Docker 环境安装 AstrBot 本体依赖后，从插件根目录运行，并将本体目录加入 `PYTHONPATH`：

```sh
python -m pytest tests -q
ruff check .
ruff format --check .
```

## 当前限制

- 尚未进行 WebUI 人工端到端验收，不支持未经验证的 Dify、Coze 等第三方 Agent。
- 初次整理前已经被压缩丢失且摘要未保留的事实无法恢复。
- 当前不自动新增原人设外的角色；新势力可在剧情有明确依据时登记。
- 尚未实现聊天编辑、重新生成或剧情回退对应的档案回滚；同一对话清空历史不会自动清空独立档案。
- 旧版档案迁移保留原有资料；旧格式没有的细分认知和初始世界书不会自动从旧文字补全，需要完整重新初始化时请新建对话。
- 当前按单进程使用，不支持多个 AstrBot 进程同时写同一数据目录。
- 场景路由使用近期文字，隐含转场或特殊称呼可能识别不到；多模态内容只处理可见文字。

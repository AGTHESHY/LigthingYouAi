# 成长角色档案

AstrBot 插件：从当前选中的人设中拆分公共设定与角色档案，每次只向主模型注入当前场景中的角色，并随剧情保存状态、经历和成长。

例如 A 原本腿伤未愈，剧情确认康复后，当前状态会更新为健康；曾经受伤及康复的经历仍保存在档案中。性格底色保留，持久的成长需要剧情依据。角色对幕后事件是否知情单独记录。

## 安装与使用

1. 使用 AstrBot 4.30 开发版或兼容的新版本。本插件开发时验证的本体是 `feb3e82c3`，版本 `4.30.0-beta.1`，尚未验证旧版兼容性。
2. 在 AstrBot WebUI 的插件页面，通过仓库地址 `https://github.com/AGTHESHY/LigthingYouAi` 安装并重载插件。也可以将仓库克隆到 `data/plugins/astrbot_plugin_living_characters`。
3. 在 AstrBot 中选择包含多个明确命名角色的人设，开启本机内置 Agent 的正常对话。无需另外重写角色卡格式，首次使用会自动整理。
4. 插件配置只有 `decision_provider_id`，默认留空。填写的是 **AstrBot 已配置的模型提供商 ID**，不是 API Key、网址或原始模型名。

模型选择：

| 配置 | 角色文字整理 | 在场判断 |
| --- | --- | --- |
| 留空 | 当前会话聊天模型 | 当前会话聊天模型 |
| 填写聊天模型提供商 ID | 指定聊天模型 | 指定聊天模型 |
| 填写原生决策模型提供商 ID，例如 Jev | 当前会话聊天模型 | 指定原生决策模型 |

推荐在 AstrBot 模型提供商中先配置 Jev，再将其提供商 ID 填入插件配置。插件复用 AstrBot 的调用能力，不需要另填密钥，也不在插件中保存服务凭据。指定的模型不可用时保留旧档案，不会静默换用其他模型写入数据。

## 与 AstrBot 的接入

检查本体后确认的顺序为：

- `main_agent/persona.py::apply_persona` 将选中的人设放进 `persona_instructions`。
- `main_agent/builder.py::build_main_agent` 随后触发 `on_llm_request`，此时完整历史尚未经过本轮压缩。插件仅替换与当前选中人设**完全匹配**的那一段，保留外围的安全、工具、技能和工作区指令。
- `tool_loop_agent_runner.py::_step` 才调用 `ContextManager.process`，执行轮次截断或 LLM 摘要。
- `MainAgentHooks.on_agent_done` 在完整 Agent 结束时通知插件。插件只保存 `completed` 的最终回复，忽略失败、取消、达到步数上限和工具循环中的中间回复。

本体没有给插件公开独立的“压缩前／压缩后”事件。因此采用**每轮维护独立档案**，不替换本体压缩器，也不修改核心文件。首次启用时在请求事件中读取当时仍可见的历史，恢复此前已发生的变化。以后在回复结束时更新，下一次压缩之前档案已经独立保存。

请求前分析只用新输入作为状态变化依据，近期历史用于理解场景，避免重复播放旧剧情。请求前的变化先用于本轮注入，只有回复成功完成后才提交。若首次整理失败，继续使用原人设；已有档案的场景分析失败时沿用上次确认的场景。

成功回复先保存为待处理剧情，再调用整理模型。调用失败时待处理剧情保留，下次请求优先重试，避免原始剧情被压缩后无法恢复。文件损坏不会触发覆盖重建。

## 档案与提示词

- **公共设定**：世界规则和写作方式。
- **核心设定**：身份、稳定背景、性格底色，初始化后不允许模型改写。
- **当前状态**：身体、位置、关系等，以最新已确认事实更新。
- **成长**：需要事件依据的持久变化。
- **重要经历**：追加保留；同一条文字不会重复添加，角色认知可以从未知变成已知。

模型提出的每项状态、成长和经历变动必须逐字引用本轮剧情作为依据。校验失败时整个更新不写入。这能拒绝没有出处的改动，但仍依赖模型正确理解语义，不能保证所有误读都被消除。

所有角色档案都保存于 `data/plugin_data/astrbot_plugin_living_characters/`。按消息来源、对话 ID、选中人设和原人设内容隔离；插件重载或重装不会删除档案。修改原人设内容会启用新的独立档案，旧文件保留。多人群聊会共享所在会话的剧情；不同对话不会共享成长。

每次注入仅包含在场角色。每位角色最多挑选 12 条相关经历，全部经历仍保存在文件里；模型未提供选择时回退到最近 8 条。角色离场不删除档案，重新入场时仍有最新状态与旧经历。角色当前背景由稳定背景与后续经历共同组成。

## 验证

25 项自动化回归测试全部通过。覆盖角色康复、旧经历保留、角色离场、原始指令保留、无依据更新拒绝、认知变化、文件损坏、会话隔离、取消与失败、待处理剧情恢复、模型选择，以及 AstrBot 本体实际的 LLM 上下文压缩器。

真实接口验证使用兼容 OpenAI 的 LLM 服务与 Jev 官方服务：

- 普通 LLM 使用 `deepseek-chat`，验证康复、假设再次受伤、镜头切换及重读档案。
- Jev 官方 `jev-latest` 能区分实际在场与仅被提及。
- 通过 AstrBot 实际 `Context.llm_generate`、OpenAI 适配器、Jev 适配器和插件请求／结束事件，验证了默认回退及原生决策模型组合。

运行测试时，将本插件的父目录和 AstrBot 本体目录加入 `PYTHONPATH`，使用独立 Conda 环境执行：

```sh
python -m pytest astrbot_plugin_living_characters/tests -q
ruff check astrbot_plugin_living_characters
ruff format --check astrbot_plugin_living_characters
```

没有把测试密钥写入源码、配置、测试脚本或安装包。

## 当前边界

- 当前版本针对内置 Agent；Dify、Coze 等第三方 Agent 不在验证范围。
- 必须有选中的人设和对话 ID；无明确角色的内容整理失败时保留原人设。
- 新登场角色需要先加入原始人设，当前不会自动创建作者未登记的角色。
- 每轮增加整理调用和等待时间；原生决策模型只能做判断，仍需要聊天模型编写档案。短人设不一定节省 token；主要收益是多角色长人设不再全部进入主模型请求。
- 更新档案的整理调用仍会读取角色资料。当前未实现海量角色检索库、分支剧情合并或跨进程同时写入。
- 当前不提供对话编辑、重新生成、回退剧情的档案回滚；在同一个对话中清空聊天记录也不会自动删除独立档案。需要重新开局时使用新的对话 ID。
- 第一次启用之前已经被压缩丢失、且摘要没有保留的事实无法恢复。多模态图片和音频不直接用于整理，只读取可见文字。
- 尚未通过 WebUI 完成端到端人工验收；本次完成了真实 SDK、压缩器回归和真实模型接口联调。
